# Контекст Trade Bot для совместной работы

Обновлено: 17 октября 2026. Перед работой сверяй этот файл с `git status` и фактическим кодом: в одной папке могут работать несколько помощников. История решений — `docs/DIALOGUE_SUMMARY.md` и git.

## Цель и договорённости

Локальное приложение для поиска торговых сигналов на криптофьючерсах и бота, который их торгует. Интерфейс и общение — на русском, понятные пользователю без подготовки разработчика. Сообщения коммитов — на русском. Репозиторий: https://github.com/mapEL21/trade-bot, ветка `main`.

**Первая версия** (решение пользователя 17.10.2026): бот «Сигнал лаборатории» на реальном счёте около 10 USDT — проверка механики исполнения, не доходности. План в `docs/ROADMAP.md`: живой режим на потоке записи → торговый адаптер Binance USDT-M через TigerX (сначала тестовая сеть; стоп на бирже, сверка состояния, защита от двойных заявок) → контроль риска → реальные заявки только после явного решения пользователя. Ключи вводит только пользователь, они не попадают в Git и базу; самостоятельно вводить секреты и совершать сделки нельзя. Не обещаем прибыль и не меняем правила ради красивого результата.

Совместимость API TigerX, фактические комиссии и применимость скидки не проверены. На скриншотах пользователя: maker 0,02%, taker 0,05%, скидка 45% — не подтверждённый тариф. В симуляции комиссия задаётся явно (по умолчанию 0,1% за круг).

## Архитектура

- `src/` — React + TypeScript + Vite. Меню: **Обзор · Боты · Лаборатория**. Страница «Журнал» удалена, события бота показываются на его странице.
  - `App.tsx` — каркас, страницы, форма бота;
  - `SignalBot.tsx` — поля настроек и панель запуска бота;
  - `SignalLab.tsx` — лаборатория (таблица сигналов, гипотеза, сессии, спреды);
  - `Scanner.tsx` — запись данных;
  - `TradeAnalysis.tsx` — общая статистика и история сделок;
  - `strategyViews.tsx` — реестр стратегий, сейчас только `signal`;
  - `model.ts` — проверка настроек и статистика;
  - `api.ts` — запросы.
- Сверху одна метка «СИМУЛЯЦИЯ», без баннеров и подписей. Индикаторы «работает / не запущено» стоят у «Ботов» и «Лаборатории».
- `server/TradeBot.Api/` — ASP.NET Core (.NET 10), SQLite.
  - `Models.cs` — `BotConfig` / `Bot` / `BotTrade`, `StrategyCatalog` с единственной стратегией `signal` / `0.1.0`;
  - `SqliteWorkspaceStore.cs` — таблицы `bots` и `events`;
  - `PaperRunStore.cs` — таблица `signal_runs`; имя осталось от удалённой симуляции, тестовые фабрики подменяют его вместе с `IWorkspaceStore`.
  - Боты удалённых стратегий («Поводырь», «Импульс») остаются в базе, но не показываются (`catalog.Known`) и не принимаются.
- `MarketScanner.cs` + `TradeBot.Recorder/ScanRecorder.cs` — **запись данных**:
  - сделки, `depth20@500ms` и ликвидации самых торгуемых фьючерсов Binance, история минутных свечей; каталог `data/scans`;
  - одна запись одновременно, авто-продление переключается во время записи;
  - монеты с размахом за 24 ч меньше `minRangePct` (4%) не пишутся.
  - В интерфейсе биржа — отдельное поле, сейчас только Binance.
- `SignalLab.cs` (`SignalDetector`, `LabPath`) + `SignalLabService.cs` — **лаборатория** (`docs/SIGNAL_LAB.md`):
  - 10 событий с фиксированными порогами: всплеск объёма, перекос агрессора, каскад ликвидаций, вынос цены, перекос стакана, пробой уровня (`LevelScanner.cs`) и 4 события плотностей (подход, проедание, снятие «подставляша», переставление «переставляша»);
  - вход через 0,25 с по встречной цене, выход через 5 с – 5 мин, по движению и против, после комиссий;
  - статистика по эпизодам, сессии `TradingSessions`, спред для пипсовки, проверка гипотезы.
  - Кэш хранится в `signal-lab-v1.json` и `signal-path-v1.ndjson` (ход цены по секундам 5 минут). `SignalDetector.Version` = 5; смена версии пересчитывает все записи. Новые записи обрабатываются сами (`Lab:AutoProcess`, его включают launcher и сервер).
- `SignalBot.cs` — **бот «Сигнал лаборатории»** (`docs/SIGNAL_BOT.md`):
  - движок `SignalEngine` идёт по обработанным записям; новые сделки появляются после обработки каждой записи;
  - запуски «с этого момента» или «с даты», API `/api/v1/bots/{id}/signal…`;
  - риск 1,5% депозита вместе с комиссиями (номинал = риск ÷ (стоп + комиссии)), стоп — N обычных минутных свечей монеты;
  - сделка пропускается, если комиссия больше 30% риска; плечо до 20x, до 3 сделок одновременно, выбор торговых сессий, лимит убытка;
  - позиция, оборванная концом записи, не закрывается выдуманной ценой.
- `StorageHousekeeper.cs` (при `Storage:Housekeeping=true`) — сжатие записей в `.gz`, удаление старше `Storage:RetentionDays`, копия базы.
- Сервер (`docs/SERVER.md`): «Обновить сервер.cmd» → linux-x64, служба `trade-bot.service`, доступ через Tailscale (`Remote:Host`). `Scanner:AutoStart` включает непрерывную запись.
- `TradeBot.Recorder` также содержит регистратор двух бирж (CLI, `docs/MARKET_RECORDER.md`) — библиотеку на будущее для других бирж. Приложение его не использует.
- Тесты:
  - `server/TradeBot.Api.Tests/` — xUnit. Фабрики обязаны подменять `IWorkspaceStore` и `PaperRunStore` на временную базу;
  - `tests/browser/*.spec.ts` — Playwright, мобильная ширина, axe;
  - `tests/*.test.ts` — модель.

## Причинность

Решения принимаются только по данным до момента решения; будущие цены, стакан или результат использовать нельзя. Неизвестный результат (оборванная запись, устаревший стакан) — это неизвестность, а не выдуманная цена. Не скрывать потерю данных. Пороги событий лаборатории фиксированы и не подгоняются под те же данные. Гипотеза проверяется только на новых данных по заранее записанному правилу.

  - Проверка — только по событиям с 16.10.2026 00:00 МСК.
  - Правило: 50 эпизодов на сигнал, плюс в целом и на обеих половинах.
  - Видно в карточке «Проверка гипотезы» (`/api/v1/lab/hypothesis`).
  - На всех данных вынос цены пока в плюсе на 20 эпизодах (с выбросом ZEREBRO), каскад в минусе.
- Запись данных идёт на стационарном компьютере пользователя. Записи переносятся на ноутбук копированием (robocopy); в git они не попадают.

## Запуск и проверки на Windows

- «Запустить Trade Bot.cmd» запускает API и сайт и открывает браузер. «Остановить Trade Bot.cmd» штатно завершает запись данных и останавливает только процессы этого запуска.
- Порты: UI 5173, API 5080. PID и журналы — `artifacts/launcher/`. Не завершать процессы node/dotnet по имени.
- Работающий API держит DLL. Собирать и тестировать можно в отдельную папку: `node scripts/dotnet.mjs test TradeBot.slnx --artifacts-path artifacts/claude-build`. Браузерные тесты против этой сборки — через конфиг в `artifacts/`.
- `pnpm build` проверяет TypeScript и собирает UI; `pnpm test` — модель; `$env:PLAYWRIGHT_CHANNEL='msedge'; node node_modules/@playwright/test/cli.js test` — браузер (порты 5081 и 5175).
- У пользователя в PowerShell может не быть node/pnpm/dotnet в PATH. Launcher находит локальные инструменты, эту возможность не ломать.
- `node node_modules/prettier/bin/prettier.cjs --write <files>` — форматирование TS и Markdown.

## Совместная работа Codex и Claude Code

Один коммит на законченный этап: код, тесты и документация вместе, после прохождения проверок; затем отправка в `main`. Не отменять чужие незакоммиченные изменения и не править одни файлы одновременно. Папку `.claude/` не включать в коммит. Секреты, записи, `.tools`, `artifacts`, базу и логи не публиковать.
