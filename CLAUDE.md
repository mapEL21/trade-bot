# Контекст Trade Bot для совместной работы

Обновлено: 17 октября 2026. Перед работой сверяй этот файл с `git status` и фактическим кодом: в одной папке могут работать несколько помощников. История решений — `docs/DIALOGUE_SUMMARY.md` и git.

## Цель и договорённости

Локальное приложение для поиска торговых сигналов на криптофьючерсах и бота, который их торгует. Интерфейс и общение — на русском, понятные пользователю без подготовки разработчика. Сообщения коммитов — на русском. Репозиторий: https://github.com/mapEL21/trade-bot, ветка `main`.

**Первая версия** (решение пользователя 17.10.2026): бот «Сигнал лаборатории» на реальном счёте около 10 USDT — проверка механики исполнения, не доходности. План в `docs/ROADMAP.md`: живой режим на потоке записи → торговый адаптер Binance USDT-M — ключами раздела Binance в Tiger.com Broker (сначала тестовая сеть; стоп на бирже, сверка состояния, защита от двойных заявок) → контроль риска → реальные заявки только после явного решения пользователя. Ключи вводит только пользователь, они не попадают в Git и базу; самостоятельно вводить секреты и совершать сделки нельзя. Не обещаем прибыль и не меняем правила ради красивого результата.

У TigerX публичного API нет (ответ поддержки Tiger.com, 18.10.2026). Ключи, созданные в разделе Binance личного кабинета Tiger.com Broker, — обычные ключи Binance API: бот работает с ними как с аккаунтом Binance. Комиссии такого подключения и доступ к фьючерсам по этим ключам не проверены. На скриншотах пользователя: maker 0,02%, taker 0,05%, скидка 45% — не подтверждённый тариф. В симуляции комиссия задаётся явно (по умолчанию 0,1% за круг).

## Архитектура

- `src/` — React + TypeScript + Vite. Меню: **Обзор · Боты · Лаборатория**. Страница «Журнал» удалена, события бота показываются на его странице.
  - `App.tsx` — каркас, страницы, форма бота;
  - `SignalBot.tsx` — поля настроек и панель запуска бота;
  - `SignalLab.tsx` — лаборатория (таблица сигналов, гипотеза, сессии, спреды);
  - `Scanner.tsx` — запись данных;
  - `TradeAnalysis.tsx` — общая статистика и история сделок;
  - `strategyViews.tsx` — реестр стратегий, сейчас только `signal`;
  - `model.ts` — проверка настроек и статистика;
  - `api.ts` — запросы.
- Сверху одна метка «СИМУЛЯЦИЯ», без баннеров и подписей. Индикаторы «работает / не запущено» стоят у «Ботов» и «Лаборатории».
- `server/TradeBot.Api/` — ASP.NET Core (.NET 10), SQLite.
  - `Models.cs` — `BotConfig` / `Bot` / `BotTrade`, `StrategyCatalog` с единственной стратегией `signal` / `0.1.0`;
  - `SqliteWorkspaceStore.cs` — таблицы `bots` и `events`;
  - `PaperRunStore.cs` — таблица `signal_runs`; имя осталось от удалённой симуляции, тестовые фабрики подменяют его вместе с `IWorkspaceStore`.
  - Боты удалённых стратегий («Поводырь», «Импульс») остаются в базе, но не показываются (`catalog.Known`) и не принимаются.
- `MarketScanner.cs` + `TradeBot.Recorder/ScanRecorder.cs` — **запись данных**:
  - сделки, `depth20@500ms` и ликвидации самых торгуемых фьючерсов Binance, история минутных свечей; каталог `data/scans`;
  - одна запись одновременно, авто-продление переключается во время записи;
  - монеты с размахом за 24 ч меньше `minRangePct` (4%) не пишутся.
  - В интерфейсе биржа — отдельное поле, сейчас только Binance.
- `SignalLab.cs` (`SignalDetector`, `LabPath`) + `SignalLabService.cs` — **лаборатория** (`docs/SIGNAL_LAB.md`):
  - 10 событий с фиксированными порогами: всплеск объёма, перекос агрессора, каскад ликвидаций, вынос цены, перекос стакана, пробой уровня (`LevelScanner.cs`) и 4 события плотностей (подход, проедание, снятие «подставляша», переставление «переставляша»);
  - вход через 0,25 с по встречной цене, выход через 5 с – 5 мин, по движению и против, после комиссий;
  - статистика по эпизодам, сессии `TradingSessions`, спред для пипсовки, проверка гипотезы.
  - Кэш хранится в `signal-lab-v1.json`. `SignalDetector.Version` = 5; смена версии пересчитывает все записи. Новые записи обрабатываются сами (`Lab:AutoProcess`, его включают launcher и сервер).
- `BotEngine.cs` + `SignalBot.cs` — **бот «Сигнал лаборатории»** v0.2.0 (`docs/SIGNAL_BOT.md`, правила — `docs/BOT_LOGIC.md`):
  - стратегия «Вынос цены · 60 с» (19.10.2026): вход и отмена как у выноса, выход через 60 с — под гипотезу № 2; на записях 16–17.10: 167 сделок, 100 → 56,33;
  - стратегии «Плотность» (отскок, выход до проедания с переворотом в пробой, снятие плотности, цель — средний отскок) и «Вынос цены» (отмена — середина выноса, выход — 60 с без экстремума, встречный сигнал, 5 минут);
  - в форме нет стопа, тейка и удержания: вход и выход — логика стратегии, у каждой сделки причина входа и выхода словами;
  - движок идёт по сырому потоку записи (детектор лаборатории ведёт стакан, плотности, проедание по ленте); результат записи для набора настроек считается в фоне и кэшируется в `bot-<ключ>.json`, сделки — в долях депозита; денежный пересчёт `SignalBots.Money`;
  - риск 1,5% депозита вместе с комиссиями до уровня отмены сценария, плечо до 20x, до 3 сделок, сессии, лимит убытка;
  - где торгует, выбирается при создании (`BotConfig.Execution`: simulation / testnet / live); у бота на бирже депозит — баланс счёта при запуске (`SignalBots.ExchangeDeposit`), лимит убытка в процентах, комиссия — по тарифу счёта (`/fapi/v1/commissionRate`, taker × 2), запуск только «с этого момента»; размер позиции — только от риска и плеча (потолок позиции убран по решению пользователя 19.10.2026);
  - правила комиссий (19.10.2026, `BotEngine.Version` 4): сделка не открывается, если комиссия больше 30% риска (все стратегии); проедание не торгуется, если обычная минутная свеча меньше трёх комиссий;
  - контроль риска: дневной лимит убытка 10% начального депозита (день по Москве, `DailyLoss`, решение пользователя 18.10.2026), без входа по стакану старше 2 с (`BotEngine.Version` 3) и по данным, опоздавшим на 3 с; остановка запуска на тестовой сети закрывает всё на его монетах;
  - исполнение через 0,25 с по лучшей цене свежего стакана или по худшей сделке после снимка; оборванная концом записи позиция не закрывается выдуманной ценой.
- `DensityScreener.cs` — **скринер плотностей** (`docs/DENSITY_SCREENER.md`, вкладка «Лаборатория» → «Плотности»): обход стаканов всех USDT-фьючерсов Binance (500 уровней, около половины лимита биржи, круг 5–8 мин); плотность — на монете с размахом за сутки от 2%, самый крупный уровень стороны в 3% от цены, втрое больше следующего, в 10 раз больше медианного и не меньше 10 минут обычной торговли монетой, засчитывается после двух кругов подряд (живой прогон: 10 плотностей на 525 фьючерсах); шаг цены `tickSize`, расстояние в шагах; статусы стоит/рядом/проедают/проели/сняли; журнал `data/screener/walls-*.ndjson`; `Screener:AutoStart` включают launcher и сервер. Источник `IDepthSource` подменяется в тестах. Общий для разных стратегий; бот «Плотность» на него ещё не переведён.
- `LiveBots.cs` — **живой режим** бота «Плотность» (`docs/SIGNAL_BOT.md`): монеты с плотностью скринера ближе 1,5% к цене (до 10) и с открытой позицией подключаются к живому потоку Binance (`BinanceLiveFeed`: depth20@100ms + aggTrade, подписка на ходу); поток идёт в тот же `BotEngine` и пишется в `data/live/<run>/<start>`, повторный прогон записи даёт те же сделки (тест `LiveBotsTests`); события `watch`, `history`, `screener` в записи; `Live:Enabled` включают launcher и сервер. Запуск «с этого момента» у плотности — живой (`SignalRun.Live`).
- `Exchange.cs` — **адаптер биржи** (`docs/EXCHANGE.md`): клиент Binance USDT-M с подписью, `ExchangeExecutor` исполняет решения движка (вход рыночной заявкой, защитный STOP_MARKET за уровнем отмены, выход `reduceOnly`, сверка, идентификаторы заявок против двойной отправки), журнал `exchange_log`. Только тестовая сеть и только живой режим; реальный счёт закрыт `Exchange:AllowLive`. Ключи — зашифрованы Data Protection в `data/exchange-keys.json`, вводит пользователь в панели на странице бота. UI — `src/ExchangePanel.tsx`.
- `StorageHousekeeper.cs` (при `Storage:Housekeeping=true`) — сжатие записей в `.gz`, удаление старше `Storage:RetentionDays`, копия базы.
- Сервер (`docs/SERVER.md`): «Обновить сервер.cmd» → linux-x64, служба `trade-bot.service`, доступ через Tailscale (`Remote:Host`). `Scanner:AutoStart` включает непрерывную запись.
- `TradeBot.Recorder` также содержит регистратор двух бирж (CLI, `docs/MARKET_RECORDER.md`) — библиотеку на будущее для других бирж. Приложение его не использует.
- Тесты:
  - `server/TradeBot.Api.Tests/` — xUnit. Фабрики обязаны подменять `IWorkspaceStore` и `PaperRunStore` на временную базу;
  - `tests/browser/*.spec.ts` — Playwright, мобильная ширина, axe;
  - `tests/*.test.ts` — модель.

## Причинность

Решения принимаются только по данным до момента решения; будущие цены, стакан или результат использовать нельзя. Неизвестный результат (оборванная запись, устаревший стакан) — это неизвестность, а не выдуманная цена. Не скрывать потерю данных. Пороги событий лаборатории фиксированы и не подгоняются под те же данные. Гипотеза проверяется только на новых данных по заранее записанному правилу.

## Запуск и проверки на Windows

- «Запустить Trade Bot.cmd» запускает API и сайт и открывает браузер. «Остановить Trade Bot.cmd» штатно завершает запись данных и останавливает только процессы этого запуска.
- Порты: UI 5173, API 5080. PID и журналы — `artifacts/launcher/`. Не завершать процессы node/dotnet по имени.
- Работающий API держит DLL. Собирать и тестировать можно в отдельную папку: `node scripts/dotnet.mjs test TradeBot.slnx --artifacts-path artifacts/claude-build`. Браузерные тесты против этой сборки — через конфиг в `artifacts/`.
- `pnpm build` проверяет TypeScript и собирает UI; `pnpm test` — модель; `$env:PLAYWRIGHT_CHANNEL='msedge'; node node_modules/@playwright/test/cli.js test` — браузер (порты 5081 и 5175).
- У пользователя в PowerShell может не быть node/pnpm/dotnet в PATH. Launcher находит локальные инструменты, эту возможность не ломать.
- `node node_modules/prettier/bin/prettier.cjs --write <files>` — форматирование TS и Markdown.

## Совместная работа Codex и Claude Code

Один коммит на законченный этап: код, тесты и документация вместе, после прохождения проверок; затем отправка в `main`. Не отменять чужие незакоммиченные изменения и не править одни файлы одновременно. Папку `.claude/` не включать в коммит. Секреты, записи, `.tools`, `artifacts`, базу и логи не публиковать.
