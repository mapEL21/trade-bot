# Торговый адаптер биржи

Адаптер превращает решения бота в заявки на Binance USDT-M. Сейчас работает только **тестовая сеть Binance**: там ненастоящие деньги и настоящий механизм биржи. Реальный счёт выключен в коде. Его включает только `Exchange:AllowLive`, а эта настройка нигде в проекте не задана.

## Какие стратегии работают

Адаптер не знает стратегий. Он получает от движка бота три решения:

- «войти» — монета, сторона, размер в долях депозита, цена и уровень отмены идеи;
- «выйти»;
- «сверить состояние».

Любая стратегия движка (`BotEngine`), которая открывает и закрывает позиции, исполняется на бирже без доработки адаптера. Заявки отправляются только из **живого режима**, то есть бот «Плотность» с запуском «с этого момента». У «Выноса цены» живого режима пока нет. Когда он появится, тестовая сеть станет доступна и ему.

## Что происходит при входе

0. **Риск.** Вход не отправляется, если данные опоздали больше чем на 3 секунды (`Exchange:MaxDelayMs`), достигнут лимит убытка запуска или дневной лимит. Размер позиции не больше потолка бота.
1. **Ограничения.** Перед входом проверяются предел убытка, шаг количества и цены монеты, минимальное количество и минимальный номинал биржи. Если заявка меньше минимума, она не отправляется, и об этом есть запись в журнале.
2. **Маржа и плечо.** Маржа изолированная. Плечо — наименьшее, при котором хватает на размер позиции, но не больше «Макс. плечо».
3. **Вход.** Рыночная заявка.
4. **Защитный стоп.** Сразу после входа на бирже ставится `STOP_MARKET` (closePosition, цена маркировки). Он стоит на 0,3% дальше уровня, где идея бота перестаёт действовать. Это страховка на случай, если бот или связь упадут. Обычный выход делает логика стратегии раньше.
5. **Если стоп не встал**, позиция сразу закрывается. Позиции без стопа на бирже не остаётся.

Выход: бот снимает свой стоп и закрывает позицию рыночной заявкой `reduceOnly`. Результат в журнале — оценка с комиссией из настроек. Фактическая комиссия видна в истории сделок на бирже.

## Защита от ошибок

- **Повторные заявки.** У каждой заявки свой идентификатор (`newClientOrderId`). Если ответ биржи потерялся, адаптер ищет заявку по этому идентификатору и не отправляет её второй раз.
- **Сверка.** Каждые несколько секунд позиции сверяются с биржей.
  - Позиция, которую закрыл защитный стоп, отмечается «закрыта биржей».
  - О чужой позиции на монете есть одна запись «внимание». Бот её не трогает.
- **Остановка бота.** Остановка закрывает его позиции на бирже.
- **Выключение приложения.** Позиции остаются с защитными стопами на бирже.
- **Журнал.** Каждое действие (вход, защитный стоп, выход, ошибка, отказ) записывается в журнал заявок и видно на странице бота.

## Ключи

Ключи вводит только пользователь, в панели «Тестовая сеть Binance» на странице бота «Плотность».

1. Войти на [testnet.binancefuture.com](https://testnet.binancefuture.com). Это отдельный сайт с тестовыми USDT, не основной аккаунт Binance.
2. Создать API-ключ в разделе API Key.
3. Вставить ключ и секрет в панель и нажать «Сохранить и проверить».

При сохранении сервер запрашивает у биржи баланс и сохраняет ключи, только если биржа их приняла. Ключи хранятся зашифрованными (ASP.NET Data Protection) в `server/TradeBot.Api/data/exchange-keys.json` только на этом компьютере. В Git, базу и интерфейс они не попадают. Удалить их можно кнопкой «Удалить ключи».

После этого при запуске бота выберите «Исполнение: Тестовая сеть Binance».

## Настройки

| Настройка                                        | Значение                                                                                                            |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| `Exchange:TestnetUrl`                            | Адрес тестовой сети, по умолчанию `https://testnet.binancefuture.com`. Если Binance сменит адрес, его задают здесь. |
| `Exchange:KeysPath`                              | Где хранить зашифрованные ключи.                                                                                    |
| `Exchange:TestnetKey` / `Exchange:TestnetSecret` | Ключи из окружения вместо файла (для сервера).                                                                      |
| `Exchange:AllowLive`                             | Реальный счёт. Не задан: включается только по отдельному решению пользователя.                                      |

## Не проверено

- Совместимость API TigerX: ждём ответа поддержки.
- Фактические комиссии и скидка.
- Поведение на реальном счёте.

До этого реальные заявки не отправляются.
