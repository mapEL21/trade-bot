# Лаборатория сигналов

Вкладка «Лаборатория сигналов» на странице «Лаборатория». Задача — найти на записанных данных события, после которых сделка даёт плюс **после спреда и комиссий**, вместо того чтобы угадывать стратегию. Это исследование: сделок и заявок нет.

## Данные

Все **завершённые** записи данных («Запись данных», `data/scans`, есть `summary.json`; сжатые читаются так же). Каждая запись обрабатывается один раз (`SignalDetector`, `SignalLab.cs`), результат хранится рядом с ней в `signal-lab-v1.json`. Новые завершённые записи обрабатываются сами раз в 5 минут (`Lab:AutoProcess`; включают launcher и сервер, в тестах выключено), кнопка «Обработать новые записи» запускает то же сразу; обрабатываются только записи без такого файла; при изменении правил (`SignalDetector.Version`) все записи пересчитываются. С версии 3 рядом пишется `signal-path-v1.ndjson` — ход цены по секундам 5 минут после каждого входа для бота «Сигнал лаборатории» (`docs/SIGNAL_BOT.md`); таблица от этого не меняется.

## События (пороги фиксированные)

Только по данным до момента события, отдельно по каждой монете. Первые 5 минут живых сделок монеты событий нет — нужен фон. Одно событие одного типа по монете не чаще раза в минуту (кроме пробоев).

| Событие           | Условие                                                                                                   | Направление                              |
| ----------------- | --------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| Всплеск объёма    | объём сделок за 10 с ≥ 5× среднего 10-секундного за предыдущие 15 мин                                     | куда ушла цена за эти 10 с               |
| Перекос агрессора | объём за 10 с ≥ 2× среднего и ≥ 80% покупок (≤ 20% — продажи) агрессором                                  | сторона перекоса                         |
| Каскад ликвидаций | ≥ 3 ликвидации в одну сторону за 10 с                                                                     | ликвидации шортов — вверх, лонгов — вниз |
| Вынос цены        | ход цены за 30 с ≥ 3× среднего размаха минутной свечи за последний час                                    | сторона хода                             |
| Перекос стакана   | в пределах 0,3% от цены заявок одной стороны больше на 60%+; считается момент, когда стакан «перевесился» | в сторону перевеса                       |
| Пробой уровня     | пробой уровня по правилам `LevelScanner` с любой оценкой                                                  | сторона пробоя                           |

## Как измеряется результат

- Вход через **0,25 с** после события по **встречной** лучшей цене стакана: покупка по ask, продажа по bid.
- Выход через **5 с, 15 с, 1 мин, 5 мин** тоже по встречной цене. Спред оплачивается дважды, как в реальной сделке taker.
- Каждое событие считается в обе стороны: **по движению** и **против движения**.
- Из результата вычитаются **комиссии круга** (по умолчанию 0,1%, меняется в интерфейсе без пересчёта записей).
- Если стакан был старше 2 с в момент входа или выхода, результат на этом горизонте неизвестен и не учитывается — более поздняя цена не подставляется. Если по монете ещё не было ни одного снимка стакана, вход неизвестен (версия 2: раньше такое событие получало вход по цене 0, и расчёт таблицы падал с делением на ноль).

Не учтены: проскальзывание глубже лучшей цены (важно для крупных заявок), задержка больше 0,25 с, funding.

## Как читать таблицу

**Эпизод** — события одного типа и направления, начавшиеся в пределах 10 с друг от друга на любых монетах. Общий рывок рынка, который сработал на десяти монетах, — одно наблюдение, а не десять. Результат эпизода — средний результат его событий; средний результат, доля прибыльных и половины считаются **по эпизодам**. **«Устойчиво»** — не меньше 100 эпизодов и плюс на обеих половинах (первые и вторые 50% эпизодов по времени).

Комбинаций 48, поэтому часть из них окажется в плюсе случайно. Устойчивая комбинация — кандидат, а не стратегия. Поле **«Только события с»** (дата и время, запоминается в браузере) оставляет в таблице и на графике только события начиная с этого момента: гипотеза, сформулированная по старым данным, проверяется на данных, которых при её выборе не было. Подгонять пороги событий под эти же данные нельзя.

По клику на строку — график результата этого сигнала (сделки по 100 USDT; сплошная линия с комиссиями, пунктирная без) и список сделок.

## Зафиксированная гипотеза (16 октября 2026)

По первым 2,2 часа записей (до 16.10.2026): после **принудительного рывка цены** — «вынос цены» (ход за 30 с ≥ 3 обычных минутных свечей) или «каскад ликвидаций» — сделка **по движению** с удержанием **5 минут** даёт плюс после комиссий. Вынос цены: 9 эпизодов, +1,24% в среднем после комиссий 0,1%, 6 из 9 в плюсе; каскад ликвидаций: 68 эпизодов, +0,05% (половины −0,03% / +0,13%). Эпизодов слишком мало, чтобы верить. Проверка — только на событиях **с 16.10.2026 00:00** (поле «Только события с»): нужно хотя бы 30–50 эпизодов выноса цены, то есть несколько суток сканера. Правила и пороги до проверки не меняются.

**Правило вывода** (зафиксировано 16 октября 2026, до появления проверочных данных; `SignalLab.Hypothesis`, карточка «Проверка гипотезы» над таблицей): проверяются два сигнала — «Вынос цены» и «Каскад ликвидаций», по движению, 5 минут, комиссии круга 0,1%, только события с 16.10.2026 00:00 МСК. Каждому нужно **50 эпизодов**. Набравший их сигнал **подтверждён**, если средний результат после комиссий выше нуля и в целом, и на обеих половинах эпизодов, иначе **не подтвердился**. Гипотеза подтверждена, если подтвердился хотя бы один сигнал, и отвергнута, если оба не подтвердились. Пока эпизодов меньше 50, промежуточное среднее показывается с пометкой «пока», вывода нет. Подтверждение — повод для бота в живой симуляции, а не доказательство прибыли.

## API

- `GET /api/v1/lab/status` — обработка записей: `idle` / `running` / `finished`, сколько обработано.
- `POST /api/v1/lab/run` — обработать новые записи (409, если уже идёт).
- `GET /api/v1/lab/report?feePct=0.1&fromMs=` — таблица по всем записям (`fromMs` — только события с этого момента, мс от 1970 г.).
- `GET /api/v1/lab/hypothesis` — проверка зафиксированной гипотезы: эпизоды каждого сигнала, нужное число, среднее, половины, вывод `collecting` / `confirmed` / `rejected`.
- `GET /api/v1/lab/trades?type=&mode=follow|fade&horizon=5|15|60|300&feePct=&fromMs=` — сделки выбранного сигнала для графика.

Первый прогон (15 октября 2026, 2 записи, около часа активного рынка, 20 монет, 867 событий): после комиссий все комбинации в минусе; до комиссий лучше других «каскад ликвидаций против движения» (+0,07% за 5 с), но событий 20 — это шум. Нужны многие часы записей.
