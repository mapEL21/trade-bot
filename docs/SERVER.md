# Trade Bot на сервере

Сервер работает круглосуточно: сканер пишет рынок, симуляции ботов идут без открытого ноутбука, данные хранятся на сервере. Реальных заявок по-прежнему нет.

Что нужно: VPS с **Ubuntu 24.04**, 2–4 ядра, 4–8 ГБ памяти, от 100 ГБ диска, без ограничения трафика. Лучше всего Япония (Токио, рядом с серверами Binance), затем Сингапур или Гонконг. Не США — Binance их не обслуживает. Аренду и оплату делаете вы; пароли и ключи от хостинга никому не передавайте.

## 1. Первый вход и проверка Binance

После заказа хостинг даст IP-адрес и пароль `root`. На Windows откройте PowerShell:

```
ssh root@IP-АДРЕС
```

На сервере проверьте, что Binance отвечает с этого адреса:

```
curl -s -o /dev/null -w "%{http_code}\n" https://fapi.binance.com/fapi/v1/ping
```

`200` — всё в порядке. `451` или `403` — Binance не обслуживает эту площадку: попросите хостинг сменить локацию (Сингапур, Гонконг).

Удобно сразу настроить вход по ключу, без пароля (один раз, на Windows):

```
ssh-keygen -t ed25519
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@IP-АДРЕС "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```

## 2. Установка

На Windows, в папке проекта: дважды щёлкните **«Обновить сервер.cmd»** и введите IP-адрес. Скрипт соберёт приложение для Linux (на сервере не нужны .NET и Node), загрузит его и установит. Адрес запоминается на этом компьютере.

Установщик создаёт:

- службу `trade-bot` — стартует при включении сервера и перезапускается после сбоя;
- приложение в `/opt/trade-bot`, данные в `/var/lib/trade-bot` (база, записи рынка, записи сканера, копии базы);
- настройки в `/etc/trade-bot/trade-bot.env` — создаются один раз и при обновлениях не меняются.

По умолчанию на сервере: непрерывная запись данных (новая запись каждый час, 20 монет от 150 млн $ и с размахом за сутки от 4%, `Scanner__MinRangePct`), сжатие завершённых записей, удаление записей старше 14 дней, копия базы раз в сутки (последние 7). Изменить: `sudo nano /etc/trade-bot/trade-bot.env`, затем `sudo systemctl restart trade-bot`.

Обновление после новых изменений в проекте — тот же **«Обновить сервер.cmd»**. Сервер штатно останавливается (дописывает записи, завершает запись данных), заменяет приложение и запускается снова; данные и настройки остаются. Прошлая версия лежит в `/opt/trade-bot.previous`.

## 3. Доступ к интерфейсу через Tailscale

Приложение слушает только сам сервер (`127.0.0.1:5080`) и не имеет входа по паролю, поэтому в интернет его **не открываем**. Доступ — через Tailscale: частная сеть между вашими устройствами, для остальных сервер закрыт.

1. Зарегистрируйтесь на tailscale.com, установите Tailscale на ноутбук и телефон, войдите.
2. На сервере:

   ```
   curl -fsSL https://tailscale.com/install.sh | sh
   sudo tailscale up
   ```

   Откройте показанную ссылку и подтвердите вход своим аккаунтом.

3. Включите HTTPS-адрес для приложения:

   ```
   sudo tailscale serve --bg 5080
   ```

   Tailscale покажет адрес вида `https://trade-bot.tail1234.ts.net` (при первом запуске может попросить включить HTTPS в панели Tailscale — следуйте ссылке).

4. Сообщите приложению этот адрес (без `https://`):

   ```
   sudo nano /etc/trade-bot/trade-bot.env
   ```

   строка `Remote__Host=trade-bot.tail1234.ts.net`, затем `sudo systemctl restart trade-bot`.

5. Откройте адрес на ноутбуке или телефоне — это тот же интерфейс, но работающий на сервере.

Без Tailscale можно зайти через SSH-туннель: `ssh -L 5080:127.0.0.1:5080 root@IP-АДРЕС`, затем на ноутбуке открыть `http://127.0.0.1:5080`.

Брандмауэр не обязателен (приложение не слушает внешнюю сеть), но не помешает: `sudo ufw allow OpenSSH`, затем `sudo ufw enable`. Сначала разрешите SSH, иначе потеряете доступ.

## 4. Перенос ботов с ноутбука (по желанию)

Остановите приложение на ноутбуке («Остановить Trade Bot.cmd»), затем на Windows:

```
scp server\TradeBot.Api\data\workspace.db root@IP-АДРЕС:/tmp/workspace.db
ssh root@IP-АДРЕС "systemctl stop trade-bot && install -o trade-bot -g trade-bot -m 640 /tmp/workspace.db /var/lib/trade-bot/workspace.db && systemctl start trade-bot"
```

Боты, их запуски, сделки и шаблоны перенесутся. Записи рынка с ноутбука переносить не обязательно.

## Полезные команды на сервере

- состояние: `systemctl status trade-bot`
- журнал в реальном времени: `sudo journalctl -u trade-bot -f`
- перезапуск: `sudo systemctl restart trade-bot`
- место на диске: `df -h /var/lib/trade-bot`; состояние хранения видно и на вкладке «Лаборатория» → «Запись данных»
- копии базы: `/var/lib/trade-bot/backups`

## Что важно знать

- Перезапуск сервера прерывает идущие симуляции: они помечаются «прервано», как и на ноутбуке. Непрерывный сканер после перезапуска продолжает сам.
- Сжатые записи (`events.ndjson.gz`) анализируются так же, как обычные.
- Удаление записей старше `Storage__RetentionDays` дней необратимо. `0` — хранить всё (следите за диском).
- Когда дойдём до реальной торговли с ключами, защиту сервера нужно будет усилить отдельно.
