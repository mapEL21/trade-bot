# Локальный API v1

ASP.NET Core / .NET 10. API слушает только loopback, по умолчанию `http://127.0.0.1:5080`.
Vite пересылает запросы `/api` на этот адрес. Описание OpenAPI: `/openapi/v1.json`.

Это локальный однопользовательский сервер без авторизации. Доступ через интернет, проброс портов и многопользовательский режим пока не предусмотрены. Для них потребуется отдельная авторизация.

## Стратегия и экземпляр

Каталог `StrategyCatalog` содержит метаданные версий. Сейчас зарегистрирован только `impulse` / `0.1.0` со статусом `planned`, `canCreate: true`, `canRun: false`. Это разрешает сохранить черновик настроек, но не выполнять торговый код. Произвольные DLL, скрипты и API-ключи не принимаются.

Экземпляр привязан к ID и версии стратегии, бирже и инструменту. Создание не выделяет реальные средства и не проверяет торговую доступность символа. Поля баланса и лимита — настройки будущего запуска.

## Методы

| Метод  | Путь                      | Результат                                                         |
| ------ | ------------------------- | ----------------------------------------------------------------- |
| GET    | `/api/v1/health`          | Состояние процесса; `executionEnabled: false`.                    |
| GET    | `/api/v1/strategies`      | Каталог версий стратегий.                                         |
| GET    | `/api/v1/workspace`       | Согласованный снимок: до 100 экземпляров и последние 200 событий. |
| POST   | `/api/v1/bots`            | Создать экземпляр; `201`, объект бота и заголовок `Location`.     |
| GET    | `/api/v1/bots/{id}`       | Экземпляр и `ETag` с номером ревизии.                             |
| PUT    | `/api/v1/bots/{id}`       | Сохранить настройки, увеличить ревизию.                           |
| DELETE | `/api/v1/bots/{id}`       | Удалить экземпляр и записать событие; `204`.                      |
| POST   | `/api/v1/bots/{id}/start` | `409`: алгоритм не реализован.                                    |

Снимок ограничен небольшим локальным пространством; пагинация потребуется при снятии лимита в 100 экземпляров. Сделки всегда пусты, статус всегда `draft`. Полей для записи сделок, статуса и произвольной истории нет.

Тело POST/PUT — объект `config` из формата импорта, без внешней обёртки `schemaVersion`. Неизвестные JSON-поля отклоняются. Максимальный размер запроса — 32 КБ. Деньги на сервере представлены типом `decimal`.

Изменяющие запросы требуют `X-TradeBot-Client: web`. PUT/DELETE дополнительно требуют `If-Match: "1"` с текущей ревизией. Устаревшая ревизия получает `412`, отсутствие ревизии — `428`. Это предотвращает потерю изменений между вкладками. Создание через POST не повторяется клиентом автоматически: при потере ответа сначала нужно обновить список.

Ошибки возвращаются в формате Problem Details: `400` для валидации, `403` для недопустимого источника запроса, `404` для отсутствующего бота, `409` для ограничения состояния, `429` для лимита запросов, `503` при ошибке SQLite. Подробности SQL и трассировки не возвращаются клиенту.

## Исследование рынка

Анализ сохранённых записей:

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/api/v1/research/recordings` | `{ items, unavailable }`; до 100 последних каталогов, повреждённые пропускаются и считаются в `unavailable`. |
| GET | `/api/v1/research/recordings/{id}/analysis` | Последний сохранённый отчёт; `404`, если его ещё нет. |
| POST | `/api/v1/research/recordings/{id}/analysis` | Рассчитать и сохранить отчёт. Тело: `{ impulseBps: 3, windowMs: 250, entryDelayMs: 100, holdMs: 1000, maxAgeMs: 1000, feeBps: 5, slippageBps: 1 }`. Нужен `X-TradeBot-Client: web`. |

Ошибки анализа: `400` — параметры/ID; `404` — нет файла; `409` — запись не завершена или занят анализатор; `422` — повреждение/лимит формата; `408` — отмена/таймаут; `503` — файловая ошибка. Формулы, ограничения и трактовка: [MARKET_ANALYSIS.md](MARKET_ANALYSIS.md).

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/api/v1/research` | Снимок текущей/последней сессии; при запуске сервера `idle`. |
| GET | `/api/v1/research/markets?sourceExchange=bybit&exchange=okx` | `{ sourceExchange, exchange, updatedUtc, instruments: [{ coin, symbol }] }`: общие активные инструменты выбранных бирж. Биржи: `hyperliquid`, `binance`, `bybit`, `okx`; `400` для неизвестных или одинаковых бирж, `503` при недоступности каталога. Кэш 5 минут отдельно для каждой направленной связки. Без `sourceExchange` используется Hyperliquid. |
| GET | `/api/v1/research/stream` | SSE, JSON-снимок раз в секунду. Закрытие подписки не останавливает запись. |
| POST | `/api/v1/research` | `{ "sourceExchange": "bybit", "exchange": "okx", "coin": "ARB", "seconds": 60, "maxMb": 256 }`; `202` и ID после принятия команды. Проверка рынка и подключение асинхронны. По умолчанию источник Hyperliquid, биржа сравнения Binance. Одинаковые биржи отклоняются до запуска. |
| POST | `/api/v1/research/{id}/stop` | `202` для текущей сессии, включая уже завершённую; `409`, если ID сменился. |

Старт и остановка требуют того же заголовка клиента и проверки Origin, что остальные мутации. `400` — недопустимые параметры/поля, `409` — уже идёт запись или её завершение. Повторный старт автоматически не выполняется. После потери ответа состояние нужно получить из монитора. Тикер проходит серверную валидацию; длительность 1–3600 секунд, размер 1–1024 МиБ. Путь и адреса соединений клиент не задаёт.

Снимок содержит состояние, инструмент, лимиты, время записи, число событий, байты, разрывы, последние 12 событий журнала, потоки выбранных площадок и BBO. Поля `sourceExchange` и `exchange` задают направление, `sourceSymbol` и `symbol` — обозначения инструмента. Цены и количества BBO передаются десятичными строками. `executionEnabled` всегда `false`. Состояние `recording` само по себе не означает свежесть каждого потока — проверяются отдельные статусы и возраст котировок.

Проекция котировок обновляется в потоке записи после файлового API, отдельно от WebSocket-приёма. SSE не читает файлы и не обращается к биржам. Контроль ордеров и торговые ключи отсутствуют. Подробнее о свежести и ограничениях — [регистратор рынка](MARKET_RECORDER.md).

## Хранение настроек

По умолчанию база — `server/TradeBot.Api/data/workspace.db`; папка игнорируется Git. Таблицы `bots` и `events` обновляются одной транзакцией. Номер схемы — `PRAGMA user_version = 1`; повреждённая или более новая база не заменяется пустой автоматически.

Данные старого демопространства остаются в localStorage и доступны по `/?demo=1`. Они не переносятся в базу автоматически. Для переноса настроек экспортируйте JSON в деморежиме и импортируйте в серверном пространстве; вымышленные сделки не переносятся.

Настройки окружения: `Storage__Path` — путь SQLite, `Api__Port` — локальный порт, `Ui__Origin` — разрешённый адрес интерфейса. Они нужны, в частности, для отдельной тестовой базы. SQLite используется для первого локального этапа; PostgreSQL остаётся вариантом для последующего серверного развёртывания.
