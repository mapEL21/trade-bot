# Навыки ECC для Trade Bot

## Текущий этап: веб-интерфейс

| Навык            | Для чего применяется                                                                               |
| ---------------- | -------------------------------------------------------------------------------------------------- |
| `react-patterns` | Состояние React, чистота рендера, обработчики событий, очистка эффектов и композиция компонентов.  |
| `frontend-a11y`  | Подписи полей, ошибки форм, клавиатура, фокус модальных окон и доступные названия кнопок.          |
| `browser-qa`     | Пользовательские сценарии Playwright, ошибки браузера, адаптивность и автоматическая проверка axe. |

Навыки применяются к локальному демопрототипу. Проверки браузера не подтверждают корректность торгового алгоритма или готовность к реальным деньгам. Первые скриншоты служат начальной точкой: сравнения с утверждённым визуальным эталоном пока нет. Автоматическая проверка доступности не заменяет проверку скринридером.

Для экрана «Исследование рынка» эти же навыки применены к жизненному циклу SSE, отмене подписок, блокировке устаревшего сравнения, управлению серверной сессией и проверке трёх размеров экрана. Браузерные фикстуры отделены от реальных потоков; отдельно выполнена проверка запуска и остановки настоящей публичной записи через UI.

## Серверный этап

Применены `dotnet-patterns`, `api-design` и `csharp-testing`: типизированные модели, DI на границе хранилища, версия API v1, серверная валидация, транзакционное сохранение и интеграционные тесты xUnit с WebApplicationFactory и настоящей SQLite.

## Следующие этапы

Для спецификации DEX → CEX и публичного регистратора применён `latency-critical-systems`: время получения данных, p50/p95/p99, ограничение очереди и разделение записи и приёма. `dotnet-patterns` и `csharp-testing` применены к реализации и тестам регистратора. Короткая реальная сессия измерила только задержку приём → запись в файл; задержки бирж, опережение и исполнение не установлены. Алгоритм и подключения к торговым аккаунтам не реализованы.

Кандидаты для подключения по мере появления соответствующего кода:

| Навык                      | Этап                                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------------------ |
| `dotnet-patterns`          | Сервер ASP.NET Core и торговый движок C#.                                                        |
| `csharp-testing`           | Проверка ордеров, риск-лимитов, восстановления состояния и расчётов.                             |
| `api-design`               | Контракт между интерфейсом, API и движком.                                                       |
| `latency-critical-systems` | Измерение задержек и оптимизация обработки рыночных событий после появления работающего контура. |
| `security-review`          | Серверные ключи бирж, авторизация и проверка команд перед подключением аккаунта.                 |

Это подбор для проекта, а не установка всех навыков сразу. Навыки для LLM-трейдинга не нужны: использование языковой модели для торговых решений не запланировано.
