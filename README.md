# Trade Bot

Платформа для автоматизированной торговли фьючерсами с веб-интерфейсом, управлением собственными ботами и отдельной статистикой по каждому боту.

**Статус:** интерфейс React / TypeScript подключён к локальному серверу ASP.NET Core / .NET 10. Настройки экземпляров и журнал сохраняются в SQLite. Экран «Исследование рынка» показывает публичные котировки любых двух разных бирж (Hyperliquid, Binance, Bybit, OKX), загружает общие активные пары в список с поиском и управляет записью; регистратор также запускается отдельно из консоли. Торговый алгоритм и подключения к торговым аккаунтам ещё не реализованы.

В разделе «Стратегии» показаны наши алгоритмы и их версии. **Стратегия — код алгоритма, экземпляр бота — его настройки для конкретной биржи и инструмента.** Пока «Импульс» отмечен как «В разработке»: создать черновик можно, запустить торговлю нельзя.

Рабочее пространство загружается с локального сервера; отдельного демопространства больше нет. Боты стратегии «Поводырь» работают в живой симуляции по публичным данным бирж, их сделки, баланс и статистика помечены как симуляция. При недоступности сервера интерфейс показывает ошибку и ничего не подставляет.

## Первая версия

- Первый кандидат — lead–lag: сигнал с площадки-поводыря, сделки на отстающей площадке. Алгоритм реализован как симуляция на записи; живое торговое исполнение ещё не подключено.
- Один бессрочный фьючерс на альткоин. BTC и ETH исключены из первого отбора.
- Для первого исследования выбрана связка Hyperliquid (публичный источник сигнала) → X Binance (планируемое исполнение через TigerX). Инструмент ещё предстоит выбрать по записям рынка и ограничениям заявок.
- Подключение собственного бота к TigerX пока не подтверждено. Поддержка стандартного биржевого API не означает совместимость с TigerX.
- Баланс около 10 USDT — целевой размер теста механики исполнения, если позволяют минимальный ордер и требования к марже. Доходность такого теста не служит оценкой устойчивости стратегии.
- Список ботов, карточка со статистикой, настройки, история сделок и журнал событий.
- Импорт и экспорт настроек наших стратегий с указанием версии; без API-ключей и стороннего исполняемого кода.
- Явное разделение симуляции и реальной торговли: реальных заявок и торговых ключей в приложении нет.

## Как пользоваться приложением

1. Открыть «Стратегии» и выбрать «Создать экземпляр», либо перейти в «Мои боты».
2. Создать бота из доступной стратегии или импортировать его настройки.
3. Задать биржу, символ фьючерса, выделенный баланс и лимит убытка.
4. Открыть карточку бота и проверить вкладки «Обзор», «Сделки», «Настройки» и «Журнал».
5. Экспортировать конфигурацию в JSON или сделки примера в CSV.

Новые боты создаются без сделок. Менять биржу, символ и начальный баланс бота с историей можно через создание копии, чтобы не приписывать старые результаты новым настройкам.

Стратегия описывает алгоритм. Бот — отдельный экземпляр стратегии с конкретным аккаунтом, инструментом, версией и настройками.

## Технологии

| Компонент                                  | Выбор                    |
| ------------------------------------------ | ------------------------ |
| Торговый движок и стратегии                | C# / .NET                |
| Сервер приложения и API                    | ASP.NET Core             |
| Веб-интерфейс                              | React / TypeScript       |
| Настройки, заявки, исполнения и статистика | PostgreSQL               |
| Исследование записей рынка                 | Python при необходимости |

Реализованы клиент React 19 / Vite 7 и сервер ASP.NET Core / .NET 10. Торговый движок пока запланирован.

## Требования к будущему торговому движку

- Закрытие браузера не останавливает торговый движок.
- «Пауза» запрещает новые входы, продолжая управление открытой позицией.
- «Остановить и закрыть» — отдельное действие; отправленная заявка на закрытие ещё не означает закрытую позицию.
- Каждая заявка и исполнение связаны с ботом и версией стратегии.
- Ограничения аккаунта действуют дополнительно к ограничениям бота.
- Реализованный PnL, нереализованный PnL, комиссии, funding и кешбэк учитываются отдельно.
- Реальная торговля выключена по умолчанию.
- Ключи, секреты, выгрузки аккаунтов и приватные торговые данные не публикуются в репозитории.

## Запуск и проверка

### Запуск двойным кликом в Windows

В уже подготовленном проекте откройте **«Запустить Trade Bot.cmd»** в корне папки. Он соберёт сервер, запустит сервер и сайт в фоне и откроет браузер. Окно запуска после этого можно закрыть. Повторный запуск не создаёт дубликаты. `pnpm` и `node` в системном `PATH` не требуются: скрипт ищет локальный .NET SDK и Node.js, включая установленную среду Codex.

Для остановки откройте **«Остановить Trade Bot.cmd»**. При активной записи скрипт сначала запрашивает её остановку и ждёт сохранения до 45 секунд. Если сервер недоступен или запись не завершилась, он оставляет сервер работать и показывает ошибку. После штатного завершения останавливаются только процессы, созданные этим запуском и прошедшие проверку PID, времени создания, исполняемого файла и команды. Другие программы не затрагиваются. Это локальный запуск для разработки; окна браузера не закрываются, записи и база остаются на диске.

Если приложение уже запущено вручную, сначала остановите запись на сайте и закройте прежние процессы через Ctrl+C в их терминалах. Скрипт не присваивает себе процессы, запущенные другим способом, и не освобождает занятые порты принудительно.

Журналы и сведения о процессах находятся в `artifacts/launcher/` и не публикуются в Git. На новом компьютере сначала установите зависимости и инструменты по инструкции ниже. Файлы `.cmd` можно запускать из любого каталога; при необходимости создайте на рабочем столе обычные ярлыки на них.

### Ручной запуск и подготовка нового компьютера

Нужны Node.js 22.18+, pnpm 11 и [.NET SDK 10](https://dotnet.microsoft.com/download/dotnet/10.0). Установленная только среда Runtime не подходит для сборки.

```sh
pnpm install --frozen-lockfile
pnpm build:api
pnpm dev:api
```

Во втором терминале:

```sh
pnpm dev
```

Открыть http://127.0.0.1:5173. API слушает только локальный адрес на порту 5080; база создаётся в `server/TradeBot.Api/data/workspace.db`. Шрифт включён в сборку.

Скрипты `dev:api`, `build:api` и `test:api` используют SDK из `.tools/dotnet`, если он установлен локально, иначе системный `dotnet`. SDK и база не публикуются в Git.

```sh
pnpm build
pnpm test
pnpm test:api
pnpm exec playwright install chromium
pnpm test:ui
```

В Windows для браузерных тестов можно использовать установленный Edge:

```powershell
$env:PLAYWRIGHT_CHANNEL = 'msedge'
pnpm test:ui
```

Перед браузерными тестами выполните `pnpm build:api`. Playwright запускает отдельные серверы на портах 5081 и 5175 с базой `artifacts/browser-workspace.db`. Рабочая база пользователя не используется. Тесты проверяют сохранность после перезапуска API, конфликт ревизий, серверную валидацию, отказ запуска неготовой стратегии, работу интерфейса и ошибки сети. Скриншоты остаются в игнорируемой папке `artifacts/`.

## Формат импорта

JSON содержит только конфигурацию поддерживаемого шаблона. Неизвестные поля, API-ключи и неизвестные версии отклоняются. Максимальный размер файла — 32 КБ.

```json
{
  "schemaVersion": 1,
  "config": {
    "name": "Мой импульс",
    "exchange": "Binance",
    "symbol": "ARBUSDT",
    "budget": 10,
    "lossLimit": 1,
    "strategy": "impulse",
    "strategyVersion": "0.1.0"
  }
}
```

Доступность символа на бирже и достаточность маржи в прототипе не проверяются. Импорт не переносит программный код, историю сделок или статус запуска.

## Работа с репозиторием

Первая фьючерсная стратегия доступна как **симуляция на записи**: «Исследование рынка» → выбрать завершённую запись → «Проверить первую стратегию». Начальный участок определяет кандидата в поводыря, следующий используется для проверки входов и выходов; сравниваются два направления входа и четыре задержки. В настройках выбирается модель исполнения: по записанному стакану с номиналом, пределом цены и частичными исполнениями либо упрощённая BBO. Журнал объясняет сделки и пропуски; денежный итог включает только полностью закрытые сделки. Это отдельный исследовательский модуль; торговые карточки и API-исполнение пока не запускаются. [Правила стратегии](docs/STRATEGY_REPLAY.md).

В исследовании рынка доступен анализатор завершённых записей: качество данных, реакция цены в обоих направлениях и условные входы с комиссией, задержкой и проскальзыванием. Отчёты сохраняются локально. Подробнее: [методика анализа](docs/MARKET_ANALYSIS.md). Это исследовательская оценка, не подтверждение прибыльности стратегии.

Сообщения коммитов пишем на русском языке и кратко описываем внесённые изменения.
